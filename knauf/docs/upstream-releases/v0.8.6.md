# Upstream v0.8.6 — release notes for the Knauf fork

**Upstream tag:** `v0.8.6` (`566e20b61`, committed 2026-05-31)
**Merged into fork:** `1da02a301` (merge commit on `chore/upstream-v0.8.7`, 2026-07-08)
**Upstream baseline before this sync:** `v0.8.5`
**Range:** `upstream/v0.8.5..upstream/v0.8.6` — 294 commits
**Upstream changelog:** <https://www.librechat.ai/changelog/v0.8.6>

> **TL;DR** — v0.8.6 is the **observability + hardening** release. It adds first-class ops surface (Prometheus `/metrics`, OpenTelemetry tracing, readiness endpoints, graceful shutdown) and a large security sweep (MCP SSRF, OpenID token-reuse, tenant-context, and — most relevant to us — stripping post-login fields out of the unauthenticated `/api/config`, which forced the Knauf `config.js` payload split). Nothing here breaks a Knauf seam; the config change is the only one that required resolution, and it's done.

This doc is built from the verified git range, not the marketing changelog. PR numbers are upstream `danny-avila/LibreChat` PRs.

## New features available to Knauf

### Observability & ops
- **Prometheus metrics endpoint** (#13265, #13111) — `/metrics` in Prometheus exposition format. **Enable:** set `METRICS_SECRET` in `.env`; the endpoint returns `401` for every request until it is set (verified: our boot returns `401` today because it's unset). Wire it to a scrape target in the AGK deployment once the secret is provisioned.
- **Backend OpenTelemetry tracing** (#12909) + **SSE stream-lifecycle tracing** (#13266) — spans across the request and streaming path. **Enable:** standard `OTEL_*` env (exporter endpoint/headers); off when unset. Pairs naturally with the planned Langfuse rollout.
- **Explicit readiness endpoints** (#13212) — `/livez` (liveness, always `200`) and `/readyz` (`503` until init completes, then `200`). **Operator action:** point the k8s liveness/readiness probes at these instead of `/health`. Confirmed live in our boot smoke.
- **Graceful HTTP shutdown on SIGTERM/SIGINT** (#13211) — drains in-flight requests before exit; complements `/readyz` for zero-drop rollouts.
- **Configurable HyperDX browser RUM** (#13287) — front-end real-user monitoring. Knauf already runs its own Adobe Analytics + OneTrust consent stack, so this is **not** something we need to adopt.
- **Structured logging context** (#13110) and **disable file log transports** (#13215) — cleaner log shipping for containerized deploys.
- **Build metadata for support triage** (#12756) — surfaces build/version info for support.

### Providers & models
- **Claude Opus 4.8** (#13380), **Gemini 3.5 Flash** (#13231), **GPT-5.5 token definitions** (#12973), **Gemma 4 `thinkingLevel`** (#13088), model-aware max-output tokens for Gemini (#13390) — additive token/model definitions. Knauf runs Azure `gpt-5.4`/`gpt-4o`, so these are available but not on our critical path.
- **AWS Bedrock API-key** (#8690) + **AWS profile credentials** (#10504) + **Bedrock Guardrail config** (#11717, #12815) — relevant only if Knauf ever adds a Bedrock endpoint.
- **Vertex AI multi-region** (#13044), **OpenRouter prompt-cache setting** (#13029).

### Agents, tools & MCP
- **MCP remote proxy support** (#13076) — reach MCP servers through a proxy. Useful for the AGK MCP rollout if servers sit behind egress control.
- **Eager execution of tool calls** (#13192) — tool calls start executing as soon as they're parsed from the stream. Behavior change (latency win); on by default.
- **Explicit "new Skill" route from the agent builder** (#13119) and **skill import size limit** (#13073) — part of the Skills groundwork that lands fully in v0.8.7.
- **Mint Code API auth tokens** (#13028) — token minting for the code-execution API.

### Files & storage
- **Signed CloudFront downloads** (#12970), **strict signed-cookie enforcement** (#13078), **region-aware S3/CloudFront keys** (#12987) — the AWS media-signing path. Knauf uses **Azure Blob + SAS** (KK20-167), so the CloudFront/S3 machinery is **N/A** for us, but note the shared `requireSignedAccess` model.
- **Decouple file-attachment persistence from preview rendering** (#12957) — attachments persist independently of preview; touches the file upload/preview path where several Knauf file seams live (see Seam interactions).

### UX & chat
- **Message navigation strip + scroll-to-bottom redesign** (#12657).
- **Hide model-spec badge rows** (#13124) — upstream option to suppress the badge cluster. Complementary to Knauf's existing `interface.webSearch:false`/`runCode:false` BYOK-badge hiding.

### Auth
- **Session cookie `Secure` override** (#13189), **OpenID multi-audience** (#13404, #13077), **MCP OAuth `audience` parameter** (#13402). See the security section — several of these are hardening as much as feature.

## Security hardening now in place

Grouped by risk class. All are now in the fork as of this merge.

### SSRF
- **Harden MCP proxy SSRF checks** (#13274) and **MCP redirect SSRF checks** (#12931) — validate the resolved address before connecting/following redirects.
- **`allowedAddresses` exemption list for SSRF-guarded targets** (#12933) + **scope `allowedAddresses` by port** (#13022) — operator allowlist (now host **and** port) for intentionally-internal MCP/URL targets. This is the shared address-guard model that Knauf's KK20-194 open-url SSRF hardening plugs into (see Seam interactions).
- **Validate avatar URL before fetch** (#12928) + **use shared IdP avatar processing** (#13422) — block server-side fetch of attacker-controlled avatar URLs; route IdP/OpenID avatars through the guarded processor.
- **Restrict user Tavily endpoint URLs** (#12946) — a user-supplied Tavily endpoint can't be pointed at an internal host.

### DoS & resource bounds
- **Cap default limit on agent-list queries** (#13382), **response-size limits for streamable-HTTP MCP responses** (#13219), **bound subagent expansion** (#13064), **bound permission-superset cache inputs** (#13065), **count rejected skill-import bytes** (#13063) — cap otherwise-unbounded work/memory across agent, MCP, and skill paths.
- **Prevent silent crash from unhandled MCP OAuth reconnect rejections** (#12812) — a global `unhandledRejection` handler stops OAuth-reconnect storms from killing the process (availability). Related to the Knauf `serverReady` boot-gating seam.

### ReDoS & input sanitization
- **Escape People-Picker search regex** (#13169) — user input was interpolated into a regex (ReDoS / injection).
- **Sanitize user response fields** (#13421) — `sanitizeUserForResponse`; strips sensitive user fields from API responses.
- **Harden configured rich-text rendering** (#13423), **sanitize HTML in admin banner & MCP config dialog** (#12927), **preserve Mermaid `foreignObject` in sanitized SVG** (#12819), **harden model-spec icon rendering** (#13356) — HTML/SVG sanitization on config-driven and model-spec surfaces. *(#13356 is the upstream change that introduced model-spec icon precedence — the same code path our `EndpointIcon.test.tsx` adaptation documents; the Knauf branding wordmark deliberately overrides it. See Seam interactions.)*
- **Harden code-env filepath uploads** (#12936), **validate Bedrock user credentials** (#13279, #13277), **protect model-spec instructions from client leakage** (#13125).

### Auth & session
- **Strip post-login fields from the unauthenticated `/api/config`** (#13102) — the big one for us. Fields only meaningful after login (custom footer, help/FAQ URL, analytics IDs) must not ship in the pre-auth payload. This forced the Knauf `config.js` payload-builder split (see Seam interactions).
- **Harden OpenID session token reuse** (#13086), **restrict OpenID JWT bearer reuse** (#13052), **honor `OPENID_REUSE_TOKENS` in admin OAuth exchange** (#13154), **support OpenID audience on refresh grants** (#13077).
- **Session cookie `Secure` override** (#13189) — pairs with the Knauf secure-cookie seam pinned by `AuthService.spec.js`.
- **Pin MCP OAuth client secrets** (#13276), **harden MCP OAuth request handling** (#13264), **restrict MCP OAuth audience in user-managed configs** (#13418).

### Tenant isolation
- **Reject system tenant in auth context** (#13278) and **restore tenant context in MCP OAuth callback** (#12782) — the tenant-context model Knauf's tenant-aware file/config seams ride on.

### Authorization
- **Enforce MCP permissions for agent tools** (#13174) + **memoize MCP permission checks per request** (#13419), **enforce skill-share role permission** (#13062), **strict opt-in skills activation per agent** (#12823) + **persist/enforce skill invocation permissions** (#12745), **sanitize agent-list skill scope** (#13122), **harden agent file-preview access** (#12981), **harden artifact routing lookups** (#13069), **scope message conversation access** (#13183), **honor admin-panel `allowedDomains` at registration** (#13204).

### Secrets & credentials
- **Pin MCP OAuth client secrets** (#13276), **filter the `user_provided` sentinel in tool-credential loading** (#12840) — the literal string `user_provided` can't be used as a real key.
- **Mint scoped Code API auth tokens** (#13028) + **decouple `bash_tool` from per-user `CODE_API_KEY`** (#12712).

### Log / telemetry redaction
- **Redact outbound telemetry URL queries** (#13133), **strip session-JWT forwarding from browser RUM** (#13414), **avoid logging the password on a login-validation error** (#12926), **strict CloudFront signed-cookie enforcement** (#13078).

### Supply chain & infra
- **Prevent CI path-argument injection** (#13284), **harden CI supply-chain workflows** (#13090), **harden Docker dev image builds** (#13041), **harden Helm chart tag parsing** (#13123), **harden data-retention semantics** (#13049), **bump `@xmldom/xmldom` to the patched (CVE) release** (#12795), **pin GitNexus native dependency + harden its index workflow** (#12937, #12935).

> This is the Knauf-relevant subset. The full v0.8.6 range carries ~60 security/hardening commits (including a large MCP-OAuth flow-hardening set); the remainder are CI/supply-chain and OAuth-flow resilience with no fork-specific surface. Sweep the range yourself with `git log upstream/v0.8.5..upstream/v0.8.6` if you need the exhaustive set.

## Config & env changes

| Change | Required? | Notes |
|---|---|---|
| `METRICS_SECRET` in `.env` | Optional (per environment) | `/metrics` returns `401` until set. Set it only where a Prometheus scraper needs access; keep unset elsewhere. |
| `OTEL_*` exporter env | Optional | Backend OTel tracing is off unless configured. Coordinate with the Langfuse/observability rollout. |
| k8s probes → `/livez` + `/readyz` | Recommended | Switch liveness/readiness probes off `/health` to the new endpoints for correct rollout gating. |
| `librechat.yaml` `version` | See v0.8.7 doc | The config-schema version gap is tracked in the [v0.8.7 notes](v0.8.7.md#config--env-changes); no v0.8.6-specific bump is required on its own. |

No secret rotation or breaking `.env` change is required by v0.8.6 alone.
