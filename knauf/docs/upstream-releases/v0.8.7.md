# Upstream v0.8.7 — release notes for the Knauf fork

**Upstream tag:** `v0.8.7` (`9e74cc0e5`, committed 2026-06-24)
**Merged into fork:** `1fac8ed85` (merge commit on `chore/upstream-v0.8.7`, 2026-07-08, stacked on the v0.8.6 merge)
**Upstream baseline before this sync:** `v0.8.6`
**Range:** `upstream/v0.8.6..upstream/v0.8.7` — 251 commits
**Upstream changelog:** <https://www.librechat.ai/changelog/v0.8.7>

> **TL;DR** — v0.8.7 is the **agent-capability + usage-visibility** release: Skills/Subagents, keyboard shortcuts, real-time token/context-usage tracking, pinned & archived chats, and a Settings redesign. For Knauf it carries **three config actions an operator must take** (re-enable memory extraction, set the admin-panel session secret, bump the config-schema version) and one privacy feature worth a decision (a configurable message PII filter, #13602, that overlaps KK20-207). The merged code builds and boots clean; the only seam work was documentation-level (test adaptations) — see Seam interactions.

Built from the verified git range. PR numbers are upstream `danny-avila/LibreChat` PRs.

## New features available to Knauf

### Agents, skills & tools
- **Model-spec subagents** (#13598) + **Skills** groundwork — agents can compose subagents and skill bundles. The Skills route (`api/server/routes/skills.js`) and agent-schema fields are present in the fork. **Enable:** interface/config surface + per-agent allowlists; not yet exposed in the Knauf builder.
- **GitHub Skill Sync** (#13293), **deployment skill directory** (#13523) — sync/serve skill bundles.
- **Report tool results per call via `onResult` channel** (#13698) — programmatic tool-calling plumbing.
- **Agent API-keys management UI** (#13819) and **resolve agent prompt time-variables in the user's timezone** (#13815).

### Usage, cost & context (large cluster — interacts with the Knauf cost seam)
- **Real-time context-window & token-usage tracking** (#13670) — live token/context gauge in the chat UI.
- **Context gauge UX: hover snapshot, click breakdown, currency, cost-on-by-default** (#13739) — **note "cost-on-by-default."** Knauf already replaced upstream `TokenUsage` with its own conversation-cost readout (`KnaufConversationCostTotal` in `ChatForm.tsx`); this upstream cost surface overlaps that seam (see Seam interactions).
- **SDK-aligned context-usage projection** (#13801), **persist context breakdown & branch/total usage cost** (#13734), **per-agent endpoint token config in multi-endpoint billing** (#13738).

### UX & chat
- **Keyboard shortcuts** (#12425) — global shortcuts + a shortcuts dialog, mounted from `Root`. On by default. *(This expanded the client hook dependency graph — `Root`/`ChatView`/`useKeyboardShortcuts` now pull `useLocalize`/`useNewConvo`/`useQueryClient`; several Knauf client test mocks were updated to match. The app code itself is upstream-clean.)*
- **Pinned conversations** (#13492) and **Archived Chats UI** (surfaced in `AccountSettings`, a11y-polished in #13874).
- **Show message timestamps on hover** (#13709) — Knauf renders `KnaufMessageHeading` over the upstream `<h2>`+timestamp on branded turns, so timestamps are deliberately **not** shown on Knauf headings (see Seam interactions).
- **Reference selected chat text with a multi-quote popup** (#13868), **message minimap navigation + bottom terminus node** (#13853).
- **Settings redesign** — registry-driven dialog, search, mobile drill-in (#13722).
- **Surface model-spec branding on landing and selector** (#13662) and **soft default model spec** (#13554) — overlaps Knauf's `default: true` KARL landing branding (KK20-159).
- **Surface agent marketplace in the model selector** (#13553) — related to the Knauf marketplace-in-sidebar work (FEAT-02).
- **Conversation starters for model specs** (#13710).

### Providers & models
- **Native Anthropic provider for custom endpoints** (#13748), **custom headers on built-in provider endpoints** (#13742), **configurable reasoning replay for custom endpoints** (#13921).
- **GPT-5.5 + frontier OpenAI models; drop deprecated defaults** (#13636), **Claude Fable 5** (#13628).
- **Google URL context + native YouTube video understanding** (#13924), **`promptCacheTtl` model parameter** (#13835), added token pricing (#13863).

### Admin, infra & observability
- **Bundle Admin Panel in Docker Compose stacks** (#13876) — matches the [`../implementation-plans/admin-panel-dev-deployment-plan.md`](../implementation-plans/admin-panel-dev-deployment-plan.md) direction. **Requires `ADMIN_PANEL_SESSION_SECRET`** (see Config & env).
- **Audit-log backend for SystemGrant assign/revoke events** (#13087) — governance-relevant.
- **Honor admin-panel MCP allowlist overrides without restart** (#13814), **reuse request-scoped MCP connections per run** (#13673).
- **Tag Langfuse traces with tenant ID** (#13808), **surface message feedback as Langfuse scores** (#13544) — align with the Langfuse rollout.

### Privacy (decision needed)
- **Configurable message PII filter** (#13602) — a native, config-driven PII filter on messages. **This overlaps [`../proposals/pii-masking-and-anonymization.md`](../proposals/pii-masking-and-anonymization.md) (KK20-207).** Evaluate it as a possible OOTB baseline before/alongside the proposed Presidio/Azure-AI-Language engines.
- **Snapshot files for shared-link attachments** (#13740), **granular access control for shared links via ACL** (#13051).

## Security hardening now in place

### ReDoS & DoS
- **Prevent ReDoS in YouTube URL extraction for URL context** (#13937).
- **Cap context-projection workload before tokenization** (#13910) — bounds the new usage-projection work so a crafted conversation can't exhaust CPU during tokenization.
- **Bound MCP `tools/list` pagination with aggregate budgets** (#13909), **cap audit-chain verification and honor client cancellation** (#13903), **bound memory-agent input** (#13606), **bound log traversal + remove the legacy `api/config` logger** (#13813).

### Authorization
- **Harden historical file authorization** (#13918) — re-authorize access to older/message-scoped files.
- **Re-check `execute_code` authorization on event-driven tool loads** (#13912) — closes a window where code execution could be re-triggered without re-authz.
- **Prune dangling skill IDs from agent allowlists** (#13702) — stops orphaned skill grants lingering on agents.
- **Restrict MCP server URL disclosure to admins/owners/editors** (#13784) — redacts operator MCP URLs + OAuth `authorization_url`/`token_url`/`revocation_endpoint` from non-editor callers.
- **Strip caller-supplied priority from assign-only config upserts** (#13911) + **preserve document priority on section-scoped config writes** (#13772) — assign-only/section-scoped grants can't reorder config precedence.
- **Scope attachment usage to the request owner** (#13557), **bind agent file context to the current turn** (#13506), **reject client-supplied subagent configuration** (#13660).
- **Add OpenID role sync** (#13415) — maps IdP roles to app roles. **Enable:** OpenID role-sync env config.

### Auth, session & secrets
- **Require an operator-supplied Admin Panel session secret** (#13902) — the admin panel refuses a blank/default session secret. **Operator action required** if the admin panel is deployed (see Config & env).
- **Use `SecretInput` for sensitive fields** (#12955) — masks secret fields in the UI.
- **Send first OpenID audience on authorization requests** (#13694), **make the OpenID token-reuse window configurable** (#13546), **reuse MCP OAuth authorization URL** (#13532).
- **Guard auth continuation with a dedicated limiter** (#13555) + **per-user throttle on 2FA continuation attempts** (#13583) — rate-limit the auth-continuation/2FA path.
- **Normalize verification-flow error responses** (#13558) — uniform errors block user-enumeration; **categorize auth tokens by flow type** (#13556); **coalesce auth recovery into a single refresh flight** (#13618).
- **Withhold custom endpoint headers from user URLs** (#13917, #13767) — operator-configured headers (may carry secrets) are never sent to user-controlled URLs; a user key is required instead. **Resolve env variables in MCP OAuth URL fields** (#13573) so secrets come from env, not inline config.
- **On-behalf-of (OBO) token exchange for MCP servers** (#13429) — Entra ID `jwt-bearer` OBO. **Enable:** `obo.scopes` in the librechat.yaml server config.

### Shared links
- **Validate shared-file cookie auth against the live refresh session** (#13908) — a shared-file cookie is checked against the current session, not trusted standalone.
- **Prevent shared-link caching + strengthen log redaction** (#13561), **harden shared-link message sanitization with an allowlist** (#13510), **gate shared startup config by link access** (#13897), **narrow the public-share 401 bypass to the share endpoint only** (#12905), **surface share-permission load errors** (#13833).

### Tenant isolation
- **Scope role-cache keys** (#13454), **app-config override cache** (#13455), and **token/skill-sync caches** (#13770, #13771) **by isolation context**; **apply the isolation plugin to distinct queries** (#13457) with a **CI guard** (#13458). **Gate request-scoped MCP servers out of the persistent tool cache** (#13672) so ephemeral per-request servers can't pollute the shared 12h cache. This is the tenant model the Knauf tenant-aware file/config seams ride.

### PII & log redaction
- **Scan all message roles in `messageFilter.pii`** (#13677) — the PII scan (see the configurable message PII filter #13602 under Features) now covers every message role, not just user turns. Directly relevant to KK20-207.

### SSRF & endpoint URL
- **Harden user-provided endpoint URL protection** (#13919) — validates user-supplied endpoint URLs (builds on the v0.8.6 SSRF address guard; complements Knauf KK20-194).

### Telemetry isolation
- **Isolate RUM telemetry proxy auth from app auth** (#13765) + **gate the RUM proxy route on `RUM_ENABLED`** (#13475) — the browser-RUM proxy no longer shares app auth. Knauf runs its own analytics stack, but note the isolation if any RUM path is enabled.

### MCP
- **Sanitize MCP tool schemas for Gemini/Vertex compatibility** (#13623), **add durable MCP config tombstones** (#13534) so deleted/revoked configs can't resurrect, **honor admin-panel MCP allowlist overrides without restart** (#13814).

> This is the Knauf-relevant subset. The full v0.8.7 range carries ~50 security/hardening commits (including a large MCP-OAuth flow-resilience set); the remainder are OAuth-flow and CI hardening with no fork-specific surface. Sweep the range with `git log upstream/v0.8.6..upstream/v0.8.7` for the exhaustive set.

## Config & env changes

Three operator actions, in priority order:

| # | Change | Required? | Detail |
|---|---|---|---|
| 1 | **`memory.agent.enabled: true`** in [`../../../librechat.yaml`](../../../librechat.yaml) | **Yes — behavioral regression if skipped** | Automatic memory extraction is now **opt-in**. Our `memory.agent` block (provider/model only, no `enabled`) means extraction is **off** after this upgrade. The server says so at boot: *"Agent config detected without explicit `enabled: true`. Automatic memory extraction is now opt-in. Add `memory.agent.enabled: true` to keep automatic memory updates."* Add the flag to restore the pre-upgrade behavior. |
| 2 | **`ADMIN_PANEL_SESSION_SECRET`** in `.env` | **Yes, if deploying the Admin Panel** | #13902 makes the admin panel refuse a blank/default session secret. Our `.env` does not set it (`.env.example` ships an empty placeholder) and Docker Compose warns it's unset. Provision a real secret before the admin panel can run. |
| 3 | **Bump `librechat.yaml` `version`** `1.3.8` → `1.3.13` | Recommended | The config schema is now `1.3.13` ([`packages/data-provider/src/config.ts`](../../../packages/data-provider/src/config.ts) `CONFIG_VERSION`); we declare `1.3.8`. The server logs *"Outdated Config version"* at boot. Bump and review the intervening keys (a few new interface/model-spec options landed across v0.8.6–v0.8.7). |

`METRICS_SECRET` / `OTEL_*` from v0.8.6 still apply — see the [v0.8.6 notes](v0.8.6.md#config--env-changes).
